## Local changes

- `rules/no-raw-advisory-lock-sql.ts` is ours and has no upstream counterpart. It rejects PostgreSQL advisory-lock calls in string and template text, so locks go through `lockAdvisory` in `packages/database/src/advisory-lock.ts`. `oxlint.config.ts` enables it for `apps/**` and `packages/**` and lists its exceptions.
- `rules/no-literal-window-instant.ts` is ours and has no upstream counterpart. It rejects a literal ISO instant that journey code binds to a window bound (a start, end, expiry, schedule, or settlement) while the instant lies after the lint clock, so fixtures derive such instants from `tools/e2e/journey-clock.ts`. `oxlint.config.ts` enables it for journey code: `apps/*/e2e/**`, `tools/e2e/**`, `tools/acceptance/**`, and `tools/verification/**`. `rules/no-literal-window-instant.test.ts` runs it through the Oxlint `RuleTester` under `node --test`, with negative controls.
- `rules/no-json-text-parameter.ts` is ours and has no upstream counterpart. It rejects JSON text, such as `canonicalJson(...)` or `JSON.stringify(...)`, as the argument of a `.json(...)` SQL parameter. The `Database` service encodes that argument, so text would be stored as a JSON string; bind `canonicalJsonValue(...)` instead. `oxlint.config.ts` enables it everywhere. `rules/no-json-text-parameter.test.ts` runs it through the Oxlint `RuleTester` under `node --test` (the package's `test` script), with negative controls.
- `rules/no-leadership-reach.ts` is ours and has no upstream counterpart. It rejects reads of the unit leadership flag (`unitLeader`, SQL `is_team_leader`) outside the reach interpreter `packages/domain/src/authz/reach.ts`, so department reach comes only from board leadership, national board leadership or a delegation (O8-11). `oxlint.config.ts` enables it for product source and lists the Organization adapters that persist the flag.
- `rules/no-hand-rolled-postgres.ts` is ours and has no upstream counterpart. It rejects running the PostgreSQL cluster programs (`initdb`, `postgres`, `pg_ctl`, `createdb`) through `postgresProgram(...)`, by name or path in a spawn call or argument array, in a shell command line, or as a path joined for them, so every cluster starts through `startDisposablePostgres` in `tools/postgres`, which waits until the server accepts connections. `oxlint.config.ts` enables it everywhere. `rules/no-hand-rolled-postgres.test.ts` runs it through the Oxlint `RuleTester` under `node --test`, with negative controls.
- `rules/no-git-history.ts` is ours and has no upstream counterpart. It rejects Git commands that read history beyond HEAD: a command that walks the commit graph (`merge-base`, `log`, `rev-list`, `describe`, and the like), an ancestor or reflog revision (`HEAD~1`, `HEAD^`, `@{1}`), a range (`main...HEAD`), or a full commit name, whether the program runs through a spawn call, an argument array, a shell command line, or a Git wrapper such as `readGitValue`. - `rules/no-owned-table-write.ts` is ours and has no upstream counterpart (spec 0006b). It rejects Drizzle `insert`, `update` and `delete` of a table that an aggregate root owns, anywhere but the aggregate writer `packages/db/src/aggregate/aggregates.ts` (which names no table), so every write to an owned table takes the owner's `Locked` token. It also rejects `update` and `delete` of a root's own table, and a `set({ state })` of a stored machine's state column, with a message of its own: only `Aggregates.apply` writes a state. It reads the declaration `packages/db/src/aggregate/ownership.ts` by relative path, the same data that the lock construct and the closure test read. The root `vite.config.ts` enables it everywhere except test files. `rules/no-owned-table-write.test.ts` runs it through the Oxlint `RuleTester` under `node --test`, with negative controls.
- `../package.json` (`@vektorprogrammet/oxlint`) is ours too (spec 0006b R3). Its `test` script runs every `rules/*.test.ts` through `node --test`, so `vp run -r test`, and with it the pre-push hook and CI, runs the `RuleTester` cases of all six rules that have them. Before it, nothing did: a rule that stopped reporting would have left every gate green.
## Rules dropped from mono-web's local extension

- `no-leadership-reach`: mono-web's unit-leadership domain semantics do not exist here.
- `no-git-history`: there is no depth-1 hosted journey contract here.
- `no-literal-window-instant`: the journey-clock/window-fixture convention is not used here.
- `no-raw-advisory-lock-sql`: tied to mono-web's `lockAdvisory`; this architecture forbids advisory locks.
- `no-json-text-parameter`: tied to mono-web's `canonicalJsonValue` and Database encoding APIs.
- `no-hand-rolled-postgres`: tied to mono-web's `startDisposablePostgres` construct.
- `no-port-probe`: tied to mono-web's `reserveLoopbackPorts` harness.
